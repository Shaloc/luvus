## Shared remote display and prepared workspace switching

- Negotiate transport 13 `session_display.v1`: one display bridge per remote host/session, retaining transport 9–12 compatibility and the existing SSH pool for older owners.
- Prepare a complete target frame before switching display and input together. Keep the current workspace usable while waiting; reject stale workspace, generation, epoch and viewport results.
- Include graphics in prepared frames and scope navigation/clipboard effects to the committed workspace. Retry only the failed display bridge.
- Let the fork installer accept transport 13 while retaining upgrades from transport 9–12.

## Remote SSH reliability and upstream integration through 51fcfe1

- Pool Unix workspace display channels across private SSH connections, with eight channels per connection. Coordinate channel slots and handshake admission across local Luvus sessions so large remote sessions do not burst past SSH MaxStartups or place every channel under one MaxSessions limit.
- Reconnect a failed display independently, preserving healthy sibling displays and the topology stream. Keep session-wide generation fencing when the topology connection fails.
- Add pane focus history back/forward and next-completed-agent navigation, including managed remote routing and workspace-tree visibility.
- Allow cursor editing inside rename dialogs and module-provided worktree creation/removal.
- Prevent accidental nested interactive clients by default, including managed remote attachment; CLI and bridge roles remain usable.
- Integrate upstream OSC 52 copy behavior through the fork's bounded, owner-routed clipboard path.
- Follow upstream's withdrawal of page-packed scrollback and its streaming redraw patches while retaining deadline cooldown and agent-only audit guards.

## Kitty graphics

- Display inline virtual images that scroll with text, including tele-style photo and mosaic placeholders, with pane-scoped image IDs and named cleanup.

- Display direct-transfer Kitty images in local and managed remote panes, with pane clipping and menu overlays.
- Update images without resending unchanged text or replacing their client-side IDs, and preserve image metadata when `NO_COLOR` is set.
- Use transport 11 builds on the display machine and remote owners for graphics; older managed owners retain text support.

This stable release includes the fork's Qoder CLI support, One themes, managed remote
sessions, reconnect fixes and confirmed remote installation. It does not promise
full Kitty protocol support or 60 FPS browser rendering. See the fork release
page for macOS ARM64 and Linux x86_64 artifacts and verification details.

## Upstream fixes and remote compatibility

- Require an observed agent transition before a prompt wait completes, and reject prompts while Codex is displaying startup or interaction screens.
- Add optional terminal identity and content revision checks to `agent.keys`, and return the matching coordinates with `agent.read`.
- Permit `pane.rename` through scoped UHP Control Access.
- Run native clipboard copy outside the UI loop, bound helper waits, and wake idle clients on failure. Retire clipboard notifications when switching local or remote owners.
- Wait for theme configuration persistence before removing a custom theme, preserving remote preference refresh.
